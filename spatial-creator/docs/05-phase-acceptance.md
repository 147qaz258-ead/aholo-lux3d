# 05 · 分阶段量化验收标准

本文件把「完成手势识别 / 完成手势交互」这类不可验收的描述，替换为**可测量、可复现、可判定**的指标。

所有"实测"列的数字来自两处，都可当场重跑：

| 来源 | 命令 | 覆盖范围 |
|---|---|---|
| 判定层基准 | `npm run bench:gesture`（需先 `npm run dev`） | 捏合/五指/校准/滤波/落点，用合成序列驱动**线上同一份代码** |
| 运行时指标 | 界面按 `M`，或 `window.__spatial.metrics.snapshot()` | 推理耗时、输入帧率、判定延迟、指针抖动、丢手次数 |

判定标记：✅ 已达标（有数字）｜⏳ 未测（需真机）｜❌ 未达标（有数字，需修）

---

## 0. 阶段划分：先把"第一阶段"钉死

需求文档只有里程碑 M0–M7，没有"第一阶段"。按手势交互的真实依赖顺序拆成 5 个阶段，**每个阶段的退出条件都是一个数字**：

| 阶段 | 对应里程碑 | 交付物 | 一句话退出条件 |
|---|---|---|---|
| **P1 输入层** | M0-Spike A/B | 摄像头 → 21 关键点 → 校准 → 稳定指针 | 捏合判定延迟 ≤100ms，指针静止抖动 <60% 原始值 |
| **P2 手势判定层** | M0-Spike C + M2 | 捏合/五指/类别 + 抓取、绘制、双手变换 | 6 类手势准确率 ≥95%，误触发 0/300 帧 |
| **P3 形变层** | M0-Spike D + M3 | 局部凹陷/拉伸/撤销 | 单次按压顶点位移可测，撤销误差 <1e-6，帧率不跌落 >20% |
| **P4 生成层** | M0-Spike E + M4 | Lux3D 文生/图生 → 入场景可编辑 | 真实任务成功率 100%，产物顶点数 >5 万可雕刻 |
| **P5 闭环层** | M5 + M6 | 保存/恢复、版本、部署 | 刷新后 100% 恢复；公网链接可访问 |

**本文档优先细化 P1，并把 P2 的实测数据一并给出**（因为"能识别几个手指、准确率多少"的答案在 P2，而它的地基是 P1）。

---

## 1. P1 输入层：范围与不做什么

**做**：拿到摄像头画面 → 每帧输出 1–2 只手的 21 个关键点 → 滤波 → 校准映射 → 指尖指针 + 实时指标。

**不做**（属于后续阶段，验收时不看）：手势语义（捏=确认）、抓取、绘制、形变、AI 生成。

**为什么必须先验收这一层**：它错了，上面所有阶段都是错的，而且错得看不出来。本轮就抓到两个这样的 bug（见 §1.6）。

### F1.3 指针映射与校准

| 指标 | 目标 | 实测 | 判定 |
|---|---|---|---|
| 校准采集样本数 | ≥30 点（4 角各一段） | 160 点（4×40） | ✅ |
| 校准后屏幕覆盖率 | ≥85%（1.0 = 满屏） | X 85% / Y 87% | ✅ |
| 重复定位精度（同一点 20 次） | ≤20px @1920 | 15px | ✅ |
| 校准耗时 | ≤5 秒 | 4 秒（设计值） | ⏳ 真机手感 |

**本轮修掉的问题**：校准采集器原来在极值外再加 6% 留边，而映射函数本身已有 4% 内缩，等于双重留边——实测覆盖率只有 76%，用户会觉得"手指够不到屏幕四边"。去掉重复留边后升到 85%/87%。

## 3. P1 明确能达到的效果（可直接对照验收）

**能做到**

1. 打开页面并授权摄像头后，画面出现实时预览，抬手即出现指针，指针位置对应指尖在画面中的位置（镜像方向正确）。
2. 校准一次（食指划四角约 4 秒）后，指尖可覆盖屏幕 85% 区域，四边留 4%–7% 可达。
3. 指针静止时抖动降低约 56%，画面上表现为"停得住"，不会持续微颤。
4. 手指移动时指针跟随滞后约 2 帧（30fps 输入下 67ms），快速来回不会拖尾。
5. 手离开画面 → 指针消失，交互自动回落到鼠标，**不会卡住或假死**。
6. 手指在画面中的位置与指针位置的对应关系可重复：同一点重复 20 次，偏差 ≤15px @1920。
7. 现场可按 `M` 读出全部数字，截图即证据。

**做不到（不要按这些验收）**

1. 不能识别"几根手指"——手指数与手势类别属于 P2，P1 只输出 21 个点。
2. 不能识别精细动作（例如"食指单独弯第二关节"）：只判定每指伸/屈，且关键点噪声 >23px 时手指数准确率会掉到 74%，达不到医疗/工业级。
3. 不能自动适配"手离镜头远近"带来的绝对尺度变化（用的是掌宽归一化比值，只能部分抵消）。
4. 双手场景只做了主手粘性与间距/角度计算，**没有验证过**两手的稳定性。

## 4. P2 手势判定层（已有实测，一并列出）

### 4.1 五指的量化含义

系统对 5 根手指各自计算伸展比，再归一化为伸展度 0..1：四指用「指尖到腕 / 指根到腕」，拇指用「指尖到腕 / 掌宽」（拇指指根离腕太近，做分母会把噪声放大数倍）。判定点 0.55、滞回 0.42，每指独立；时序上再过一层 `FingerStabilizer`（EMA α=0.45 + 逐指滞回）。**判定的是"伸/屈"二值，不是关节角度**。

| 指标 | 目标 | 实测 | 判定 |
|---|---|---|---|
| 手指数（0–5）单帧准确率 | ≥95% | 100%（200 样本，σ=0.004） | ✅ |
| 手指数稳态准确率（保持姿态） | ≥98%，翻转 0 | 100%（150 帧，σ=0.008≈15px），翻转 0 | ✅ |
| 手势类别准确率（开/拳/指/剪刀/捏/散） | ≥95% | 100%（240 样本） | ✅ |
| 类别混淆 | 允许"拳 ↔ 捏"在极端姿态下二义 | 0 混淆（6×40 全对） | ✅ |
| 判定所用坐标系 | 与画面一致（镜像后） | 是 | ✅ |

**旧实现为什么只有 92.5%**：直接拿比值比阈值，食指伸直 1.64、阈值 1.50，只剩 0.14 余量，按 15px 噪声折算约 2σ，半屈姿态会逐帧翻转。改成"归一化伸展度 + 0.55/0.42 滞回 + EMA"后单帧 100%、稳态翻转 0。

**但准确率有使用区间**：σ 扫描显示 8‰ 时单帧降到 93%，12‰ 降到 74%。也就是说关键点抖动超过约 23px（手离镜头远、逆光、背景杂乱）时不能再声称 95%。这条限制写进验收，不藏。

### 4.2 捏合（触头/触点程度）

捏合强度 = 拇指指尖到食指指尖距离 / 掌宽，映射到 0..1：

| 参数 | 比值区间 | 物理距离（掌宽按 10cm） | 含义 |
|---|---|---|---|
| 完全张开 | ≥1.30 | ≥13cm | 强度 0 |
| **按下阈值（默认 0.62）** | 0.587 | **5.9cm** | 判定为"按下" |
| **释放阈值（滞回 0.48）** | 0.748 | **7.5cm** | 判定为"松开" |
| 完全贴合 | 0.15 | 1.5cm | 强度 1.0 |

| 指标 | 目标 | 实测 | 判定 |
|---|---|---|---|
| 拾取延迟（阈值穿越 → 指针按下） | ≤100ms | 66.7ms（2 帧 @30fps） | ✅ |
| 释放延迟 | ≤150ms | 100ms（3 帧） | ✅ |
| 张开手静止误触发 | 0 次 / 300 帧 | 0 次，最大强度 0.239（阈值 0.62，余量 0.38） | ✅ |
| 捏合保持掉线 | 0 次 / 300 帧 | 0 次，最低强度 0.949（释放阈值 0.48） | ✅ |
| 连续 10 次捏合成功率 | 10/10 | 未测（合成序列只测单次） | ⏳ 真机 |

**需要真机确认的一点**：默认阈值对应"两指相距 5.9cm 就算按下"。这个偏早，真人放松时拇指食指常在 7–8cm，容易误触。建议真机先试 `0.70`（4.7cm 按下 / 6.3cm 松开），把"落点距离"收进 3–5cm。

## 6. 本轮抓到的两个真实缺陷（说明为什么 P1 必须先量化）

这两个 bug 都藏了整整一轮开发，肉眼和截图都看不出来：

| # | 缺陷 | 表现 | 根因 | 修复 |
|---|---|---|---|---|
| 1 | 一欧元滤波时间单位错 | 滤波器等价于**直通**，滑动条无效，抖动全靠 MediaPipe 自己 | `performance.now()` 是毫秒，`alpha()` 的时间常数按秒算，dt 被当成 33 秒 | dt 除以 1000；截止频率重映射 4.0Hz↔0.8Hz |
| 2 | x / y 共用一个滤波器实例 | **y 轴几乎不动**（时间常数放大 33 倍），指针只能横向移动 | 同一实例连续调用两次，第二次 `t - tPrev = 0` → alpha≈0.01 | 每关键点每轴独立实例；按左右手重建，避免串手 |

第 2 条用真手一试就会暴露（"指针上不去"），但开发环境只有假视频流，所以一直没暴露。这就是为什么 P1 的验收**必须**在真机上做。

## 7. P1 验收操作（照做即可判定）

```bash
cd spatial-creator
npm run dev            # 终端 1：前端（5173）
npm run bench:gesture  # 终端 2：判定层基准，输出 §2/§4 的数字
```

基准通过线（自动对比，人工判读）：

| 项 | 通过线 | 参考实测 |
|---|---|---|
| 捏合拾取延迟 | ≤100ms | 66.7ms |
| 张开手误触发 | 0 次 / 300 帧 | 0 |
| 捏合掉线 | 0 次 / 300 帧 | 0 |
| 抖动下降 | ≥50% | 55.7% |
| 跟随滞后 | ≤100ms | 66.7ms |
| 校准重复精度 | ≤20px @1920 | 15px |
| 手势类别准确率 | ≥95% | 100% |
| 手指数准确率 | ≥95% | 100%（单帧 σ=4‰）／100% 稳态（σ=8‰） |

真机手工验收（5 分钟）：

1. 点「启用摄像头并进入」，允许权限 → 预览出现，`HAND TRACK` 变绿。
2. 抬手 → 指针出现；**上下左右各移动一次**，确认两个方向都跟随（这条专门检查上面的 bug 2）。
3. 按 `M` 打开指标面板 → 「手在画面」应接近 100%，「丢手」不增长。
4. 手指悬停不动 5 秒 → 「指针抖动」应有数值且很小（<3‰）。
5. 点「校准」，食指划四角 → 完成后指尖可达屏幕四角附近（覆盖率 ≥85%）。
6. 手指快速左右往返 5 次 → 指针不拖尾、不卡顿；「渲染」≥50fps（真机）。
7. 手移出画面 → 指针消失，鼠标可继续操作。

判定：2、3、4、5、6、7 全部通过 = P1 验收通过。

## 8. 明确测不出来的部分

| 项 | 为什么测不了 | 需要什么 |
|---|---|---|
| MediaPipe 对真人手的检测准确率 | 合成数据只覆盖"关键点之后"，检测本身是黑盒 | 真机 + 至少 3 人 × 5 分钟 |
| 真实使用中的误触发率 | 与握姿、光照、背景相关 | 连续使用 10 分钟，靠面板统计捏合次数 / 实际意图次数 |
| 捏合手感的舒适阈值 | 纯主观 | 真人试 0.62 / 0.70 / 0.75 三档打分 |
| 长时稳定性（30 分钟以上） | 无连续运行环境 | 挂机 30 分钟看内存与丢手次数 |
| 手部录制回放回归 | 录制功能未实现 | 待办：把真机 landmark 序列存 JSON，固化为回归样本 |

最后一条是 P1 的下一件事：**没有录制回放，真机调好的参数无法被自动回归保护**，下次改代码只能再找人试一遍。
