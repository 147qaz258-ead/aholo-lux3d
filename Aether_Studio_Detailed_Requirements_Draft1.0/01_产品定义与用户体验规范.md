# Aether Studio｜产品定义与用户体验规范

**文档编号：** AS-PD-001\
**版本：** Draft 1.0\
**基线日期：** 2026-11-17\
**功能资产依据：** Feature Inventory v2（270 项）\
**文档性质：** 产品目标、用户任务、交互原则和产品验收框架

------------------------------------------------------------------------

## 1. 产品定义

### 1.1 产品定位

Aether Studio 是一个运行于 PC
浏览器、以普通摄像头为手部输入设备、以屏幕实时三维场景为创作空间的 AI
三维创作工具。

产品的核心不是把传统建模软件中的鼠标点击替换成手势，而是建立一套以手部动作直接表达空间操作意图、以
AI 协助构建复杂三维内容、以可编辑场景持续保存创作上下文的工作方式。

产品需要让用户能够完成四类核心活动：

1.  **直接操控形体：**
    指向、抓取、移动、按压、拉伸、旋转和缩放三维对象。
2.  **空间绘制：**
    在三维工作空间中绘制轨迹，将轨迹转换成可继续编辑的几何对象。
3.  **AI 连续共创：**
    根据文字、草图、当前对象和场景上下文生成或修改内容，并把结果写入当前场景。
4.  **零件与装配：**
    将复杂模型组织为独立零件，建立连接关系，支持局部修改、替换和装配。

### 1.2 产品愿景

用户不需要先理解复杂的传统建模命令，也不需要在 AI
生成器和三维编辑器之间反复切换。用户可以通过手部动作表达"抓住这里""把这一块压下去""把这个部件拉长""在这里增加一个零件"等创作意图，AI
在当前场景中协助完成更复杂的几何构建。

### 1.3 产品成功不是功能数量

Feature Inventory v2 记录 270 项已有实现资产，但这 270
项不构成完整产品需求，也不代表 270 项均已通过用户体验验收。

产品完成度必须通过以下层次判断：

  层次         判定标准                               证据
  ------------ -------------------------------------- --------------------
  实现存在     代码中有对应实现                       源码、调用链
  可触达       用户有可用入口                         实际 UI/输入操作
  功能正确     输入后行为符合规格                     功能测试
  体验达标     准确性、响应、稳定性、易用性达到目标   量化测试和用户测试
  任务闭环     用户能独立完成真实创作任务             端到端任务测试
  产品可交付   保存、恢复、导出、异常恢复均满足要求   交付验收

### 1.4 V1 产品边界

  ----------------------------------------------------------------------------------------------
  项目                                V1 定义
  ----------------------------------- ----------------------------------------------------------
  运行平台                            PC 浏览器

  输入设备                            普通 RGB 摄像头

  主要交互输出                        屏幕实时三维工作空间

  XR/VR                               不作为 V1 前提

  深度摄像头                          不作为 V1 前提

  绝对空间追踪                        不作能力承诺

  物理触觉                            不作能力承诺

  手部空间映射                        由摄像头关键点、校准和场景映射计算，不等于房间级绝对坐标
  ----------------------------------------------------------------------------------------------

**重要技术边界：** MediaPipe 的手部局部 world landmarks
以手部几何中心为参考，不是房间坐标；普通单目 RGB
摄像头也不能直接测量用户施加在虚拟模型上的真实物理力。产品中的接触、深度和按压强度必须明确为软件推算的交互量。

## 2. 用户与使用情境

### 2.1 目标用户假设

当前不提前把产品锁定为专业建模师工具，也不默认所有用户都是零基础。V1
先验证以下候选人群：

  -------------------------------------------------------------------------------------------
  候选用户                典型任务                           需要验证的产品价值
  ----------------------- ---------------------------------- --------------------------------
  三维初学者              快速构建简单形体、修改外观         是否比传统建模流程更容易理解

  创意表达者              用草图和自然语言表达想法           是否能减少建模学习和操作成本

  有经验的三维设计者      修改局部形体、生成部件、快速装配   是否能提高概念设计效率

  AI 创作者               生成模型后继续修改                 是否能解决 AI
                                                             输出不可编辑、上下文断裂的问题
  -------------------------------------------------------------------------------------------

### 2.2 首要用户任务

V1 的首要任务定义为：

**用户从空白场景开始，创建或生成一个简单三维对象，通过手势调整形体，调用
AI 增加一个部件，继续编辑并保存为可重新打开的作品。**

任务步骤：

1.  打开工作空间。
2.  启用摄像头。
3.  完成手部校准。
4.  在场景中创建基础对象或绘制初始形体。
5.  通过手势选择和移动对象。
6.  对对象进行至少一种局部形变。
7.  请求 AI 新增一个对象或部件。
8.  预览并接受 AI 结果。
9.  继续通过手势编辑生成结果。
10. 保存项目。
11. 关闭并重新打开项目。
12. 检查对象、变换、形变和关系是否保留。

### 2.3 任务成功定义

一次任务只有同时满足以下条件，才算成功：

-   用户没有由开发人员代替完成核心操作。
-   用户创建或生成了至少一个有效三维对象。
-   用户至少完成一次有效手势编辑。
-   AI 生成结果进入当前场景（若该轮任务包含 AI）。
-   原有对象没有发生未授权修改。
-   项目保存成功。
-   重新打开后核心对象和关键属性保持一致。

任务成功率：

\[
TaskSuccessRate=`\frac{成功完成任务人数}{开始任务人数}`{=tex}`\times100`{=tex}%
\]

首轮探索性测试目标：≥80%。该值是本项目初始产品目标，不是行业标准；应在真实用户测试后调整。

## 3. 核心产品主线与功能完成标准

### 3.1 主线 A：实时直接操控三维形体

用户需要感受到手部动作与模型变化之间稳定、连续、可预测的关系。

完整能力包括：

-   手部输入与坐标映射。
-   场景目标命中。
-   悬停和接触反馈。
-   抓取开始、持续和释放。
-   对象移动。
-   局部按压和凹陷。
-   局部拉伸。
-   双手缩放和旋转。
-   操作取消、撤销和恢复。
-   手部丢失保护。

完成标准不能只是"捏合后模型动了"。至少需要通过： - 操作启动成功率。 -
操作释放成功率。 - 目标对象选择正确率。 - 端到端响应延迟。 -
静止状态抖动。 - 移动跟随误差。 - 误触发率。 - 追踪丢失后的安全恢复。 -
连续操作成功率。 - 用户舒适度评价。

### 3.2 主线 B：空间绘制

完整能力包括： - 绘制模式进入与退出。 - 绘制平面选择。 -
起笔、持续采样、暂停、恢复、结束和取消。 - 轨迹实时预览。 -
去噪和平滑。 - 轨迹生成独立对象。 - 轨迹移动、编辑、合并和拆分。 -
曲线、管状体和闭合面转换。 - 保存和恢复。 - 将草图作为 AI 输入。

完成标准： - 轨迹与用户意图路径的偏差可测。 - 轨迹中断率可测。 -
手部动作到轨迹显示延迟可测。 - 生成对象可选择和编辑。 -
轨迹保存恢复一致。 - 用户能独立完成指定草图任务。

### 3.3 主线 C：AI 连续共创

完整能力包括： - 自然语言输入。 - 当前对象选择和上下文引用。 -
草图输入。 - 参考图输入（若 V1 支持）。 -
新增对象、局部修改、替换和补全任务类型。 - 生成任务状态。 -
结果预览、接受、拒绝和重试。 - 生成结果转换为场景对象。 -
多轮上下文保留。 - 版本比较和回退。 - 生成结果继续手势编辑。

完成标准： - 请求成功率。 - 生成耗时 P50/P95。 - 输出结构有效率。 -
生成结果进入场景成功率。 - 未授权对象修改次数为 0。 -
生成对象继续编辑成功率。 - 多轮任务上下文保持率。 - 保存恢复完整率。 -
用户对结果符合意图程度的评价。

### 3.4 主线 D：零件与装配

完整能力包括： - 对象转为独立零件。 - 零件身份和层级。 - 连接点定义。 -
连接类型。 - 对齐。 - 装配。 - 拆卸。 - 替换。 - 装配体整体变换。 -
零件独立编辑。 - AI 对装配上下文的理解。 - 装配关系保存恢复。

完成标准： - 零件身份稳定。 - 连接位置误差可测。 -
连接关系正确率可测。 - 替换零件后未受影响零件保持不变。 -
装配关系保存恢复完整。 - 用户能完成指定装配任务。

## 4. 全局交互原则

### 4.1 手势不强制替代所有输入

以下操作允许保留鼠标和键盘： - 文本输入。 - 文件选择。 -
精确数值输入。 - 浏览器和操作系统原生弹层。 - 调试和开发期操作。

产品目标是让核心三维创作任务可以通过手势与 AI
完成，而不是追求所有功能都能手势触达。

### 4.2 每个连续操作必须有明确生命周期

任何持续性手势操作必须定义：

`Idle → Candidate → Active → Update → Release / Cancel / Lost → Commit / Rollback`

不得只实现"触发"而不定义释放、取消和追踪丢失。

### 4.3 用户必须知道当前系统理解了什么

至少显示： - 当前工具。 - 当前目标对象。 - 当前手部追踪状态。 -
当前交互状态。 - 当前参数。 - 当前操作是否已提交。 -
当前是否有未保存修改。

### 4.4 UI 与 3D 场景必须隔离

同一次捏合不得同时触发 UI
点击和场景抓取。输入路由必须有明确优先级，并对冲突场景进行自动化回归测试。

### 4.5 操作必须可恢复

核心场景变更必须具备： - 取消未完成操作。 - 撤销已提交操作。 - 重做。 -
保存前状态保护。 - AI 修改前后版本比较。

## 5. 产品级质量目标

以下为 V1 初始目标，需在参考设备和真实用户测试中校准。

  -----------------------------------------------------------------------------------------
  维度             指标                                 初始目标 测量方式
  ---------------- ---------------------- ---------------------- --------------------------
  可用性           首次引导后任务完成率                     ≥80% 真实用户任务

  效率             核心任务耗时                     建立 P50/P95 从进入工作空间到保存成功
                                                      基线后确定 

  操作正确性       核心操作成功率                           ≥95% 标准操作任务

  手势稳定性       空闲误触发                      ≤1 次/10 分钟 无操作意图观察

  直接操控         端到端软件响应         P95 ≤100ms（候选目标） 摄像头帧到下一渲染帧

  场景保护         未授权对象修改                           0 次 操作前后场景 diff

  数据可靠性       保存恢复完整率           100%（声明支持范围） 保存/重开/导出往返

  AI 共创          生成后继续编辑成功率         ≥90%（候选目标） 生成---编辑---保存任务

  舒适度           主观操作舒适度                       首轮平均 任务后量表和访谈
                                              ≥4/5（探索性目标） 
  -----------------------------------------------------------------------------------------

## 6. 产品范围与版本策略

### V1 必须验证的核心闭环

-   普通摄像头手部输入。
-   稳定指针和捏合。
-   直接选择、抓取和移动。
-   基础局部形变。
-   空间绘制。
-   AI 新增对象并进入当前场景。
-   继续编辑生成对象。
-   保存和重新打开。

### V1 之后按价值排序的增强能力

-   多平面和更自由的空间绘制。
-   更丰富的雕刻笔刷。
-   多对象编辑。
-   完整零件连接约束。
-   AI 局部补全和多轮版本管理。
-   更丰富的导入导出格式。
-   高级网格工具。
