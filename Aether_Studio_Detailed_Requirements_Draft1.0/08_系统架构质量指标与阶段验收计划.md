**文档编号：** AS-QA-001\
**版本：** Draft 1.0\
**基线：** Feature Inventory v2（270 项现有实现资产）\
**用途：**
将产品需求、系统实现、质量指标、测试用例和阶段准入连接成完整工程闭环

# Part A. 系统架构与模块契约

## 1. 系统架构目标

系统必须支持以下完整数据流：

`摄像头 → 手部感知 → 手势语义 → 交互状态机 → UI/3D 命令 → 场景数据 → 渲染/AI/保存`

AI 生成、导入文件和用户手势必须最终进入同一个场景数据模型。不能出现 AI
生成一套独立对象、手势编辑另一套对象、保存系统又使用第三套数据结构的情况。

## 2. 建议模块边界

``` mermaid
flowchart TD
    A[Camera Input] --> B[Hand Tracking Worker]
    B --> C[Landmark / Hand Identity]
    C --> D[Gesture Semantic Layer]
    D --> E[Interaction State Machine]
    E --> F[Input Router]
    F --> G[UI Commands]
    F --> H[3D Commands]
    H --> I[Scene Model]
    J[AI Task Service] --> K[AI Asset Adapter]
    K --> I
    L[Import Adapter] --> I
    I --> M[Renderer]
    I --> N[Project Persistence]
    I --> O[Undo / Redo History]
    P[Assembly Model] <--> I
    Q[Telemetry / Test Recorder] --- B
    Q --- D
    Q --- E
    Q --- I
    Q --- J
    Q --- N
```

### 2.1 Camera Input

负责： - 摄像头权限。 - 设备选择。 - 视频流。 - 分辨率和帧率记录。 -
设备断开和恢复。

### 2.2 Hand Tracking Worker

负责： - MediaPipe 初始化。 - GPU/CPU delegate。 - 帧处理。 -
关键点输出。 - 推理错误和恢复。

不得把 UI 操作逻辑放入 Worker。

### 2.3 Gesture Semantic Layer

负责： - 五指状态。 - pinchClosure 统一语义。 - 静态姿态分类。 -
动态手势（未来支持时）。 - 手部 identity。 - 状态置信和稳定化。

输出应是语义事件，不应让每个工具直接重复解释 21 个关键点。

### 2.4 Interaction State Machine

负责： - 当前工具。 - 当前目标对象。 - Hover / Contact / Grab / Press /
Draw / Lost 等状态。 - 开始、持续、释放、取消和恢复。 - 手势事件与 UI/3D
输入路由。

### 2.5 Input Router

优先级： 1. 系统级安全/取消命令。 2. 当前已捕获的连续操作。 3. UI
控件和面板。 4. 3D 场景操作。 5. 空白区域默认行为。

同一个输入事件只能被一个操作通道消费，除非明确声明为可共享的只读反馈。

### 2.6 Scene Model

是所有编辑、AI、导入、装配和保存共用的数据源。

必须支持： - Object ID。 - Part ID。 - Assembly ID。 - Geometry。 -
Material。 - Transform。 - Visibility/Lock。 - Source/Version。 -
Connector/Relation。 - Scene Revision。

### 2.7 AI Asset Adapter

负责把不同 AI 服务输出转换为统一内部资产结构。供应商 API 不应直接耦合到
Scene Model。

### 2.8 Persistence

负责项目快照、保存、恢复、版本、导入导出和完整性校验。

### 2.9 Telemetry / Test Recorder

负责记录可复现的输入、事件和性能数据。至少支持： - 手部输入回放。 -
手势事件日志。 - 场景命令日志。 - AI 任务日志。 - 保存恢复日志。 -
测试环境元数据。

## 3. 统一事件契约

### 3.1 HandInputEvent

至少包含： - timestamp。 - handId。 - handedness。 - landmarks。 -
pinchClosure。 - fingerExtension。 - trackingState。 - sourceFrameId。

### 3.2 InteractionEvent

至少包含： - eventId。 - timestamp。 - eventType。 - activeTool。 -
targetObjectId。 - inputSource。 - confidence。 - consumedBy。

### 3.3 SceneCommand

至少包含： - commandId。 - commandType。 - targetIds。 -
beforeRevision。 - payload。 - origin（gesture / mouse / keyboard / AI /
import）。 - undoable。 - transactionId。

### 3.4 AI Task Event

至少包含： - taskId。 - requestId。 - projectId。 - sceneRevision。 -
taskType。 - status。 - inputRefs。 - outputRefs。 - cost。 -
duration。 - errorCode。

### 3.5 事件一致性

-   每个连续操作有唯一 transactionId。
-   一次拖动或一次雕刻不能按每帧创建独立 Undo Step。
-   AI 任务结果必须绑定任务 ID 和场景 revision。
-   保存必须记录保存时的 sceneRevision。
-   日志时间戳必须可比较。

# Part B. 全局质量指标

## 4. 性能指标

### 4.1 摄像头到手部状态

  指标                             初始目标 计算
  ------------------ ---------------------- -------------------------------------
  推理耗时 P95           由参考 PC 基线确定 inference end - start
  Worker 往返 P95        由参考 PC 基线确定 result received - frame sent
  手部状态更新 P95              ≤100ms 候选 hand state updated - frame received
  手部追踪可用率       ≥95% 单手、≥90% 双手 有效追踪帧/预期帧

### 4.2 手部到三维反馈

  指标                    初始目标 计算
  ------------------ ------------- -------------------------------------
  指针更新 P95         ≤100ms 候选 pointer update - camera frame
  场景变换反馈 P95     ≤100ms 候选 next render frame - gesture event
  局部形变反馈 P95     ≤100ms 候选 next render frame - pressure update
  绘制预览反馈 P95     ≤100ms 候选 next render frame - stroke sample
  交互状态反馈 P95          ≤150ms visible state update - input event

以上是软件时间，不等于真实屏幕
motion-to-photon。若需测真实物理延迟，应使用高速摄像机或外部同步装置。

### 4.3 渲染性能

标准场景： - S0：空场景 + 虚拟手。 - S1：10 个基础对象。 -
S2：一个复杂模型、多个绘制对象和常规材质。

初始目标： - S0 P95 frame time ≤16.7ms。 - S1 P95 frame time ≤33.3ms。 -
S2 P95 frame time ≤33.3ms；若未达到，必须明确设备和复杂度上限。 - 记录
P50/P95/P99，不得只记录平均 FPS。

## 5. 准确性与稳定性

  指标                               初始目标 测试
  -------------------- ---------------------- --------------------
  指针静止抖动           RMS ≤视口对角线 0.5% 静止 10 秒
  目标选择成功率                         ≥95% 标准目标任务
  捏合识别精确率                         ≥95% 标注数据集
  捏合识别召回率                         ≥95% 标注数据集
  连续操作释放成功率                  100/100 抓取/按压/绘制循环
  UI/3D 跨层误触发                0 次/100 次 冲突布局
  追踪丢失失控操作                0 次/100 次 遮挡/断开
  非目标对象意外修改                     0 次 场景 diff

## 6. AI 质量

  指标                        初始目标 测试
  ------------------------ ----------- --------------------------
  任务类型识别准确率              ≥95% 40 条固定意图测试
  有效请求完成率                  ≥95% 有效任务集
  结果结构校验通过率              ≥98% 生成结果集
  意图符合度                 平均 ≥4/5 3 名评价者或标明单人评测
  生成对象继续编辑成功率          ≥90% 生成后编辑任务

  重复请求重复写入                0 次 幂等重放
  多轮对象引用正确率              ≥95% 多轮脚本

## 7. 数据可靠性

  指标                                 初始目标 测试
  ---------------------- ---------------------- ----------------
  项目保存成功率               ≥99%（受控环境） 100 次保存
  保存恢复完整率           100%（声明支持数据） 保存/关闭/重开
  对象 ID 一致率                           100% 前后 ID 比较
  变换恢复一致率                 100%（容差内） transform diff
  装配关系恢复率                           100% relation diff
  导出再导入几何一致性         ≤0.1% 包围盒误差 round-trip
  静默数据丢失                             0 次 故障注入

## 8. 可用性和人体工学

定性体验不能只写"自然、舒适、易用"。必须使用统一任务和评分锚点。

### 8.1 任务评价维度

-   有效性：用户是否完成目标。
-   效率：完成时间、操作次数、返工次数。
-   满意度：用户对操作和结果的评价。
-   学习性：教学后是否能独立完成。
-   记忆性：间隔一段时间后能否再次使用。
-   舒适度：手臂、肩部和手指疲劳。
-   可理解性：是否知道当前工具和操作状态。

### 8.2 评分锚点

  分数   定义
  ------ ------------------------------------
  1      无法理解或无法完成
  2      多次失败，需要大量帮助
  3      可以完成，但明显不稳定或不自然
  4      基本自然，少量错误可自行纠正
  5      直觉明确、稳定、舒适，愿意继续使用

### 8.3 首轮用户测试

-   8---12 名用户用于探索性问题发现。
-   覆盖不同三维经验。
-   不允许开发人员代替用户完成核心步骤。
-   记录任务成功率、耗时、误操作、求助次数、疲劳和评分。
-   该样本不代表正式统计认证。

## 9. 测试数据和证据要求

每个验收用例必须保存： - Test ID。 - Requirement ID。 - Inventory
ID（若有）。 - Build/commit。 - PC/摄像头/浏览器信息。 - 光照和距离。 -
测试用户和样本数量。 - 操作步骤。 - 原始输入数据。 - 实际结果。 -
指标计算结果。 - 视频/日志/截图。 - Pass/Fail/Blocked。 - 缺陷编号。

不能只提交一张"成功截图"证明连续操作稳定。

# Part C. 阶段研发与验收

## 10. 阶段定义

### R0：产品需求基线

交付： - 产品定义。 - 用户任务地图。 - 功能树和需求编号。 - P0/P1/P2
优先级。 - 指标定义。 - 需求追踪矩阵。

通过条件： - P0 用户任务完整。 - 每个 P0 功能有详细规格。 -
现有实现与新增需求分开。 - 所有指标有定义、单位、测试条件和依据状态。

### R1：手部输入与直接操控

交付： - 稳定单/双手追踪。 - 校准和空间映射。 - 接触/抓取状态机。 -
对象移动。 - 按压和拉伸。 - 取消、释放和恢复。

通过条件： - 单手追踪可用率 ≥95%。 - 双手同时追踪可用率 ≥90%。 -
指针静止抖动达到目标。 - 抓取和释放达到成功率要求。 -
形变深度、半径和误差达标。 - 丢失保护 0 次失控。

### R2：空间绘制与三维编辑

交付： - 实时绘制。 - 独立轨迹对象。 - 轨迹平滑。 -
管状体/曲线/闭合面转换（按 V1 范围）。 - 基础雕刻和对象管理。

通过条件： - 绘制轨迹误差达到目标。 - 轨迹生成成功率 ≥95%。 -
对象独立性通过回归。 - 保存恢复完整。

### R3：AI 连续共创

交付： - 场景上下文。 - 草图输入。 - 新对象生成。 - 指定对象修改。 -
结果预览和接受/拒绝。 - 多轮上下文。 - 场景保护和版本回退。

通过条件： - 未授权对象修改 0 次。 - 结果结构有效率 ≥98%。 -
生成对象继续编辑成功率 ≥90%。 - 多轮对象引用正确率 ≥95%。 -
生成任务状态和异常处理完整。

### R4：零件与装配

交付： - 独立 Part。 - Connector。 - 固定连接。 - 装配体层级。 -
拆卸、替换。 - 保存恢复。 - AI 装配补件（如纳入本版本）。

通过条件： - 连接位置误差 ≤装配体包围盒对角线 0.5%。 - 连接轴角度误差
≤1°。 - 局部编辑不修改其他零件。 - 装配关系保存恢复 100%。

### R5：真实用户完整创作任务

交付： - 真实用户任务报告。 - 完整项目作品。 -
保存/重新打开/导出证据。 - 用户体验问题和改进优先级。

通过条件： - 首次引导后任务完成率 ≥80%（首轮目标）。 - 核心任务中断率
≤10%。 - 关键操作成功率 ≥95%。 - 用户能独立完成完整任务。 -
未授权数据修改为 0。

### R6：产品化和兼容性

交付： - 浏览器和设备兼容矩阵。 - 长时间运行测试。 - 大场景性能测试。 -
项目恢复和异常诊断。 - 部署、版本和帮助文档。

通过条件： - 声明支持设备矩阵全部通过。 - 30
分钟连续运行无崩溃（初始目标）。 - 保存恢复无数据损坏。 - 阻断级问题为
0。 - 支持范围和已知限制清晰。

## 11. 阶段门禁

  Gate      必须通过的条件                不通过处理
  --------- ----------------------------- --------------------
  Gate R0   需求和指标基线完整            不冻结开发范围
  Gate R1   手部输入和直接操控质量达标    不扩展复杂手势
  Gate R2   绘制和基础编辑闭环达标        修复几何/交互问题
  Gate R3   AI 生成、场景保护和保存达标   不进入装配集成
  Gate R4   零件和装配关系正确            修复数据模型和约束
  Gate R5   真实用户完成任务              根据用户结果迭代
  Gate R6   兼容、稳定和交付通过          不发布为产品版

允许提前准备下一阶段，但不得将准备工作写成当前阶段通过。

## 12. 需求追踪矩阵

每条需求至少关联以下字段：

  字段                    说明
  ----------------------- -----------------------------------------
  Requirement ID          产品需求唯一编号
  User Task ID            对应用户任务
  Inventory ID            当前已有实现资产 ID（如有）
  Priority                P0/P1/P2
  Requirement Status      Existing / Expanded / New / Research
  Implementation Status   Not Started / In Progress / Implemented
  Verification Status     Not Tested / Pass / Fail / Blocked
  Metric IDs              对应质量指标
  Test IDs                对应测试用例
  Evidence                日志、视频、报告位置
  Stage                   所属阶段

必须区分： - 需求已定义。 - 代码已实现。 - 用户入口可用。 -
技术测试通过。 - 产品体验验收通过。

## 13. 缺陷等级

  等级      定义                                     阶段规则
  --------- ---------------------------------------- ---------------
  P0 阻断   核心任务无法完成、数据丢失、严重误操作   不得通过 Gate
  P1 严重   核心体验明显失效或关键指标不达标         修复复测
  P2 一般   非核心功能或边界问题                     按计划处理
  P3 轻微   文案、视觉和低影响问题                   进入迭代

## 14. 本文档的完成标准

本文件不是所有功能的替代规格。每个功能仍需对应详细功能文档。

本文件负责： - 统一模块接口。 - 统一质量指标口径。 -
统一测试证据要求。 - 统一阶段目标和门禁。 - 统一需求追踪关系。

当具体功能规格与全局标准冲突时，必须记录差异并由产品和技术共同评审，不得默默采用较宽松的标准。
