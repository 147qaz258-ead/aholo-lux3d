# Aether Studio｜AI 连续共创详细规格

**文档编号：** AS-FS-AI-001\
**版本：** Draft 1.0\
**范围：**
自然语言输入、场景上下文、草图输入、生成任务、结果预览、场景写入、局部修改、多轮协作、版本与异常\
**产品主线：** 人与 AI 在同一个三维场景中持续共创

------------------------------------------------------------------------

## 1. 产品目标

AI 在 Aether Studio 中不是独立的"一次性模型生成器"。AI
必须能够理解用户当前正在编辑的场景，识别用户希望新增、修改或替换的对象，并把生成结果作为可编辑对象纳入当前项目。

核心要求：

1.  用户能明确告诉 AI 要新增什么、修改什么。
2.  AI 能读取本次任务所需的场景上下文。
3.  AI 能将生成任务与具体场景对象关联。
4.  用户在正式写入场景前能预览结果。
5.  AI 新增对象不得未经授权修改其他对象。
6.  AI 修改对象必须明确修改范围。
7.  生成结果必须能继续被手势工具编辑。
8.  多轮交互必须保留对象身份和任务上下文。
9.  生成失败、取消、超时或拒绝结果时，场景必须保持一致。

## 2. AI 任务类型

系统必须将用户意图转换为明确的任务类型，不得只把所有请求都当成"生成模型"。

  ------------------------------------------------------------------------------------
  Task Type               任务定义                默认场景行为
  ----------------------- ----------------------- ------------------------------------
  CREATE_OBJECT           新增一个独立对象        新增对象，不修改已有对象

  GENERATE_PART           生成一个零件            新增独立 Part，允许后续装配

  MODIFY_OBJECT           修改指定对象            只允许修改指定对象

  MODIFY_REGION           修改对象的指定区域      修改范围限制在指定区域

  REPLACE_OBJECT          用新结果替换指定对象    先预览，接受后替换，保留旧版本

  CONTINUE_FROM_SKETCH    根据草图继续生成        草图保留，生成结果作为新对象

  COMPLETE_ASSEMBLY       根据当前装配补齐零件    新增缺失零件，不擅自改动已确认零件

  EXPLAIN_SCENE           解释当前场景或对象      只返回说明，不修改场景
  ------------------------------------------------------------------------------------

### 2.1 任务分类验收

建立至少 40 条任务描述测试集，覆盖上述任务类型。

-   任务类型识别准确率初始目标 ≥95%。
-   CREATE_OBJECT 与 MODIFY_OBJECT 混淆次数必须为 0。
-   任何涉及删除、覆盖或替换的意图不明确时，必须请求用户确认。
-   任务类型置信度不足时，不得直接执行场景写入。

## 3. 用户输入规格

### 3.1 文字输入

用户可以描述： - 要创建的对象。 - 对象用途和外观。 - 尺寸或比例。 -
材质和颜色。 - 要修改的部位。 - 修改方向和程度。 -
与其他对象的连接关系。

系统必须保留用户原始提示词，不得只保存模型改写后的摘要。

### 3.2 当前对象作为上下文

用户选中对象并发出修改请求时，任务必须绑定： - projectId。 -
sceneRevision。 - targetObjectId。 - targetObjectVersion。 -
当前对象变换。 - 当前对象几何引用。 - 用户明确指定的修改范围。

如果任务执行期间目标对象已被其他操作修改，AI
结果不得直接覆盖新版本。系统应检测版本冲突并要求重新确认或基于最新版本重新生成。

### 3.3 草图输入

草图输入至少包括： - sourceStrokeId。 - 原始轨迹点。 - 平滑轨迹点。 -
工作平面 ID。 - 世界坐标变换。 - 轨迹尺寸和方向。 - 用户文字说明。

AI 必须知道草图是： - 形体轮廓。 - 结构中心线。 - 零件外形参考。 -
装配位置参考。 - 装饰线条。

若系统不能可靠判断草图语义，必须要求用户选择用途，不得静默猜测。

### 3.4 参考图输入

如果 V1 支持参考图片： - 保存图片引用和哈希。 -
记录图片是否用于整体外观、局部细节或材质参考。 -
参考图不得自动替换当前场景对象。 - 生成结果应显示与参考图的关系和限制。

### 3.5 输入完整性

提交前检查： - 任务类型。 - 用户提示词。 -
目标对象（修改类任务必需）。 - 草图/图片引用（若用户选择使用）。 -
场景上下文版本。 - 生成约束。

缺少关键输入时显示具体缺失项。不得以"生成失败"代替输入校验。

## 4. 场景上下文规格

### 4.1 上下文包

每次 AI 任务只传递与当前任务有关的上下文，至少包括：

``` ts
type SceneContext = {
  projectId: string;
  sceneRevision: number;
  activeObjectId?: string;
  objects: Array<{
    objectId: string;
    objectType: string;
    name: string;
    transform: {
      position: [number, number, number];
      rotation: [number, number, number];
      scale: [number, number, number];
    };
    bounds: {
      min: [number, number, number];
      max: [number, number, number];
    };
    source: "manual" | "stroke" | "ai" | "import";
    locked: boolean;
    visible: boolean;
  }>;
  sketches?: Array<{
    strokeId: string;
    planeId: string;
    pointsRef: string;
  }>;
  assemblyRelations?: Array<{
    relationId: string;
    parentId: string;
    childId: string;
    relationType: string;
  }>;
};
```

字段可以与项目现有数据结构统一，但上述信息类别不能遗漏。

### 4.2 上下文最小化

-   新增独立对象时，不必无差别上传所有高精度网格顶点。
-   局部修改时必须包含目标对象及必要邻接信息。
-   装配补全时必须包含连接关系和空间位置。
-   每次任务记录实际发送的上下文摘要，便于复现。

### 4.3 上下文一致性

-   任务提交时记录 `sceneRevision`。
-   任务完成时重新读取当前 `sceneRevision`。
-   若场景版本变化，先执行冲突检测。
-   不允许直接以旧上下文覆盖新场景。
-   对于新增对象任务，可以在确认新对象落点后合并；对于修改任务必须检查目标对象版本。

验收： - 100 次并发修改冲突测试中，0 次静默覆盖。 - 每个 AI
任务都能关联提交时的 sceneRevision。 -
任务结果能够追踪到输入对象和草图来源。

## 5. 生成任务生命周期

### 5.1 状态定义

`DRAFT → VALIDATING → QUEUED → RUNNING → RESULT_READY → PREVIEW → ACCEPTED`

终止状态： - REJECTED。 - CANCELLED。 - FAILED。 - TIMED_OUT。 -
CONFLICTED。

### 5.2 状态行为

  -------------------------------------------------------------------------------------
  状态                    用户看到什么                       系统允许什么
  ----------------------- ---------------------------------- --------------------------
  DRAFT                   输入内容和目标                     修改输入

  VALIDATING              正在检查请求                       不重复提交

  QUEUED                  排队等待                           取消

  RUNNING                 正在生成、阶段进度（若服务支持）   取消或离开页面后继续查询

  RESULT_READY            结果已返回                         预览

  PREVIEW                 结果预览和差异                     接受或拒绝

  ACCEPTED                已加入当前场景                     继续编辑

  REJECTED                用户拒绝结果                       重新修改请求

  CANCELLED               已取消                             重新发起

  FAILED                  失败原因                           重试或修改输入

  TIMED_OUT               等待超时                           查询任务状态或重试

  CONFLICTED              当前场景已变化                     刷新上下文并重新确认
  -------------------------------------------------------------------------------------

### 5.3 重复提交保护

-   每次用户提交生成唯一 requestId。
-   同一 requestId 的网络重试必须幂等。
-   同一任务不得重复创建两个场景对象。
-   用户主动重新生成必须创建新的 taskId，并明确关联前一任务。

验收：对同一 requestId 重放 10 次，最多产生一个正式场景写入。

## 6. 生成结果数据契约

### 6.1 结果包

AI 适配层应输出统一的内部结果包：

``` ts
type GeneratedAsset = {
  taskId: string;
  assetId: string;
  assetType: "mesh" | "curve" | "assembly";
  format: string;
  assetRef: string;
  unit: string;
  localTransform: {
    position: [number, number, number];
    rotation: [number, number, number];
    scale: [number, number, number];
  };
  bounds: {
    min: [number, number, number];
    max: [number, number, number];
  };
  materialRefs?: string[];
  sourcePromptId: string;
  sourceObjectIds: string[];
  validation: {
    parseable: boolean;
    finiteVertices: boolean;
    hasValidBounds: boolean;
    warnings: string[];
  };
};
```

该结构是产品内部契约，不预设具体供应商 API
或输出格式。适配层负责把不同服务结果转换为统一结构。

### 6.2 结果结构校验

正式写入前必须检查： - 文件或对象可解析。 - 几何顶点均为有限数值。 -
包围盒有效。 - 变换值有效。 - 材质资源引用可解析。 -
对象尺度在产品允许范围内。 - 面数/顶点数不超过当前参考设备负载限制。 -
生成对象没有空几何或不可见几何。 - 若是装配零件，连接元数据结构有效。

### 6.3 几何质量初始要求

对于支持进入场景的 Mesh： - 非有限顶点数：0。 - 包围盒尺寸必须大于 0。 -
退化三角面比例：初始目标 ≤0.5%，需用标准数据集验证。 -
法线缺失或无效时必须重算或明确提示。 - 生成对象必须能被选择和变换。 -
对于声明支持雕刻的输出类型，必须通过局部形变测试。

是否要求 watertight（封闭网格）取决于用途： -
仅用于视觉创作时，不强制所有模型封闭。 - 若用于 3D
打印或实体制造，必须进入专门的网格修复和可制造性检查流程。

## 7. 结果预览与接受

### 7.1 预览内容

用户至少能看到： - 生成对象的三维预览。 - 对象名称和类型。 -
生成尺寸。 - 当前放置位置。 - 是否为新增、修改或替换。 -
将影响哪些对象。 - 当前警告和不支持项。

### 7.2 接受规则

-   CREATE_OBJECT：接受后新增对象。
-   GENERATE_PART：接受后新增独立 Part。
-   MODIFY_OBJECT：接受后替换目标对象版本，旧版本可恢复。
-   MODIFY_REGION：只提交目标区域变化。
-   REPLACE_OBJECT：必须明确显示旧对象和新对象差异。
-   REJECTED：当前场景不发生变化。

验收： - 用户拒绝 100 次测试结果，场景对象数据必须保持不变。 -
新增任务接受后对象数量增加 1（除非任务明确生成多个对象）。 -
修改任务接受后，未授权对象的 transform、geometry 和 material
不发生变化。 - 接受动作只能提交一次。

## 8. 局部修改

### 8.1 目标范围

修改请求必须有明确范围： - 整个对象。 - 指定零件。 - 指定面/区域。 -
指定草图约束区域。

如果用户只说"把它改得更圆"，但当前选中对象不明确，系统必须先确认目标对象。

### 8.2 修改保护

对局部修改： - 目标对象 ID 必须明确。 - 修改前保存对象版本。 -
修改范围需要生成可视化影响区域或差异预览。 -
未授权对象不允许进入写入集合。 - 修改结果被接受后才提交。 -
拒绝或失败时恢复到修改前版本。

### 8.3 验收

-   100 次局部修改任务，未授权对象修改次数为 0。
-   目标对象 ID 关联准确率 100%。
-   修改范围外顶点位移为 0（定义浮点容差）。
-   旧版本恢复成功率 100%。

## 9. 多轮上下文与创作记忆

系统应维护项目内的创作上下文，而不是仅依赖聊天文本。

至少保存： - 项目 ID。 - 当前对象 ID。 - 对象名称和版本。 -
用户确认的设计约束。 - 草图引用。 - AI 任务 ID。 -
用户接受/拒绝的结果。 - 零件关系。 - 最近一次修改记录。

用户说"把刚刚那个头部再缩小
10%"时，系统必须能定位到上一轮接受的头部对象，而不是生成一个新头部。

验收： - 20 条多轮任务脚本，每条 3---5 轮。 - 对象引用正确率 ≥95%。 -
修改目标错误次数为 0（涉及多个相似对象时必须确认）。 -
用户不需要重复提供已在项目中存在的对象文件。

## 10. AI 质量评价

AI 生成质量不能只用 API success rate。

建立独立评分维度：

  维度         评分说明
  ------------ ------------------------------------
  意图符合度   是否实现用户明确描述的形态和用途
  结构完整性   是否缺少关键部件或出现明显结构错误
  几何可用性   是否可选择、变换和继续编辑
  场景匹配度   尺寸、方向和位置是否符合当前场景
  零件关系     若涉及装配，连接关系是否合理
  修改遵循度   是否只修改用户指定范围

评分采用 1---5 分锚定量表： - 1：结果错误或无法使用。 -
2：主要意图未实现，需要大幅重做。 - 3：部分符合，但需要明显修正。 -
4：基本符合，可继续编辑。 - 5：高度符合，少量或无需修正。

初始评测： - 每个主要任务类型至少 20 条固定测试提示。 - 每条提示至少运行
3 次，以观察随机性。 - 由 3 名评价者独立评分；如只有 1
名评价者，必须标记为单人主观评测。 -
意图符合度和几何可用性平均分初始目标 ≥4/5。 - 任何评分为 1
的输出必须记录失败类型。

## 11. 时延、可靠性和成本

  ------------------------------------------------------------------------------------
  指标                    初始目标/要求           说明
  ----------------------- ----------------------- ------------------------------------
  请求校验反馈            P95 ≤500ms              不含远端生成

  任务创建反馈            P95 ≤1s                 用户点击后获得 taskId

  状态更新间隔            ≤2s（任务运行期间）     若上游不支持实时状态则明确显示等待

  简单对象生成时间        P95 候选 ≤90s           需按供应商和模型基线校准

  复杂零件生成时间        P95 候选 ≤180s          需按任务类型单独统计

  有效请求完成率          ≥95%                    排除用户取消和明确无效输入

  结果结构校验通过率      ≥98%                    合法任务输出

  重复写入                0 次                    幂等测试

  未授权场景修改          0 次                    场景 diff

  任务成本记录覆盖率      100%                    每个远端任务有成本或未知状态
  ------------------------------------------------------------------------------------

90s/180s 是初始产品等待目标，不是行业标准。完成当前 AI
服务基线测量后，按真实模型和任务复杂度校准。

## 12. 异常处理

  异常               系统行为                 验收
  ------------------ ------------------------ ------------------
  输入不完整         显示缺失字段             不发起远端任务
  服务不可用         显示服务错误             场景不变
  网络中断           保留 taskId 并允许查询   不重复创建
  上游超时           查询任务状态或标记超时   不静默判定失败
  生成结果损坏       拒绝写入                 场景不变
  结果尺寸异常       显示警告或拒绝           不自动缩放掩盖
  目标对象版本冲突   标记 CONFLICTED          不覆盖新版本
  用户取消           发送取消请求并同步状态   不产生未确认写入
  用户拒绝预览       关闭预览                 场景不变
