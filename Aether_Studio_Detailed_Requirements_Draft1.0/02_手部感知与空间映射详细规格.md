# Aether Studio｜手部感知与空间映射详细规格

**文档编号：** AS-FS-HAND-001\
**版本：** Draft 1.0\
**范围：**
摄像头输入、单/双手检测、关键点、校准、屏幕映射、场景射线、追踪丢失和恢复\
**对应现有资产：** Inventory A1、A2、A3、A4、A5、B1

------------------------------------------------------------------------

## 1. 功能目标

将普通摄像头视频转换为稳定的手部交互数据，并将食指指向位置映射到屏幕三维工作空间。

系统不只需要"检测到手"，还必须保证： - 手部身份连续。 - 指针位置稳定。 -
坐标映射可重复。 - 追踪丢失可安全恢复。 -
手部与三维场景之间的映射逻辑明确。 - 用户能看懂系统是否正确识别手部。

## 2. 输入设备与运行边界

### 2.1 摄像头输入

V1 使用普通 RGB 摄像头。

每次运行必须读取并记录： - 摄像头设备 ID。 - 实际采集宽度和高度。 -
实际采集帧率。 - 视频轨道状态。 - 浏览器和操作系统版本。 -
摄像头是否启用自动曝光/自动白平衡（设备支持时）。

当前 Inventory 记录推理输入会缩放至 640×360，送帧间隔
26ms。该参数属于当前实现，不代表摄像头实际采集分辨率和帧率。

### 2.2 推荐测试输入

  项目         基线测试条件
  ------------ -------------------------------------------------
  摄像头采集   1280×720（参考设备支持时）
  模型输入     当前实现 640×360
  手部距离     0.5m、0.75m、1.0m
  水平角度     0°、±15°、±30°
  垂直角度     0°、±15°
  照度         300、500、700 lux
  测试时长     单项 60 秒；长时间测试另设 30 分钟
  用户样本     探索阶段至少 8 人；正式样本量根据目标置信度确定

以上是测试夹具建议，不是当前兼容性承诺。超出范围的情况应作为边界测试。

## 3. 手部检测与关键点输出

### 3.1 关键点

每只手输出 21 个关键点，至少包含： - landmark index。 - x、y、z。 -
timestamp。 - handedness。 - tracking confidence（若底层 API
提供对应置信度；若不提供，不得伪造）。

关键点坐标必须注明坐标空间： - 图像归一化坐标。 - 摄像头图像像素坐标。 -
屏幕 CSS 像素坐标。 - NDC 坐标。 - 三维场景世界坐标。

不得将这些坐标混用。

### 3.2 支持手数

V1： - 同时追踪 1 只手为基础能力。 - 同时追踪 2 只手为双手操作能力。

验收： - 单手标准条件追踪可用率 ≥95%。 - 双手同时追踪可用率 ≥90%。 -
每次测试 60 秒，至少 3 次重复。 - 追踪可用率 = 有效输出帧数 /
预期输出帧数。 -
手离开画面期间不计入有效帧分母，但必须单独统计离开和重新捕获时间。

### 3.3 左右手身份连续性

系统必须维护稳定的 hand
identity，不允许仅根据每帧的左右手分类结果随意交换手 ID。

测试动作： 1. 左手先进入画面。 2. 右手进入。 3. 两手靠近。 4. 两手交叉。
5. 一只手短暂遮挡。 6. 一只手离开并重新进入。

验收： - 100 次标准交叉测试中身份交换错误 ≤1 次。 -
若无法可靠判定身份，系统应进入 identity-uncertain
状态，不得将错误手势直接执行为高风险命令。 -
身份恢复后，必须重新确认主操作手。

### 3.4 主操作手选择

当前 Inventory 已有 stickyPrimary。产品规格要求：

-   默认主手由首次稳定进入工作区的手确定。
-   主手短暂丢失不立即切换。
-   主手持续丢失超过 500ms 后，允许进入待切换状态。
-   另一只手稳定存在至少 300ms 后，才允许切换主手。
-   切换时必须显示状态反馈。
-   双手缩放/旋转模式不依赖单一主手，但仍需保持左右手身份。

以上时间为初始工程目标，需在交叉和遮挡测试中校准。

## 4. 手指状态与捏合输入

### 4.1 五指状态

每根手指输出 0---1 的连续伸展度： - 0：完全弯曲或接近弯曲状态。 -
1：完全伸展或接近伸展状态。

必须区分： - 连续伸展度。 - 离散伸展/弯曲分类。 - 手势类别。 -
交互命令。

不能将姿态分类结果直接等同于操作命令。

### 4.2 时序稳定

现有 Inventory 记录 EMA + 滞回 0.55/0.42。验收需测试： -
稳定姿态下状态跳变次数。 - 姿态切换检测延迟。 - 不同手速下漏检率。 -
不同手型下阈值适应性。

初始目标： - 稳定保持某一姿态 10 秒，错误状态跳变 ≤1 次。 -
有效姿态转换到状态输出的 P95 延迟 ≤150ms。 - 每种声明支持的手势至少 100
次标注测试，计算 precision、recall、F1。

### 4.3 捏合闭合度

产品内部统一使用 `pinchClosure`： - 0 表示张开。 - 1
表示达到校准定义的最大闭合。

如果当前底层值为"指尖距离/掌宽"，必须统一转换方向，禁止有的模块把距离越大当越强、有的模块把闭合越紧当越强。

初始滞回： - Start threshold：0.62。 - Release threshold：0.48。 - 连续
3 个有效结果确认状态转换。 - 处于 0.48---0.62 区间时保持前一状态。

这些数值沿用当前 0.62 阈值和 0.14
滞回差作为初始基线。不同用户校准后需测试是否仍适用。

## 5. 校准流程

### 5.1 校准目标

将用户在摄像头图像中的有效手部活动区域映射到屏幕工作区域，使用户能在主要屏幕范围内稳定指向目标。

### 5.2 V1 校准流程

1.  用户点击"开始校准"。
2.  系统检查摄像头和手部追踪状态。
3.  显示四个校准目标，按左上、右上、右下、左下顺序采集。
4.  用户将食指尖移动至目标并保持。
5.  系统记录稳定关键点样本。
6.  每个角点至少采集 15 个有效帧。
7.  每个角点的坐标使用中位数或经验证的稳健估计值。
8.  四角采集完成后计算有效手部活动矩形。
9.  检查矩形宽高是否达到最低范围。
10. 计算映射参数并显示九点测试。
11. 九点测试通过后保存校准配置。

### 5.3 校准失败条件

以下任一条件触发失败： - 任一角点没有足够有效样本。 -
四角顺序错误导致映射矩形自交。 - 校准区域宽度小于视口宽度映射需求的
40%。 - 校准区域高度小于视口高度映射需求的 40%。 -
九点测试误差超过目标值。

失败后： - 保留上一次有效校准。 - 显示具体失败原因。 -
提供重新开始入口。 - 不允许把不完整校准标记为成功。

### 5.4 校准验收

  指标                           初始目标
  ---------------------- ----------------
  首次校准成功率                     ≥90%
  完整校准耗时 P50                 ≤15 秒
  九点映射误差 RMS         ≤视口对角线 2%
  九点最大误差             ≤视口对角线 4%
  校准配置保存成功率                 100%
  设备切换后旧校准误用               0 次

校准耗时目标需经新用户测试确认；四秒倒计时本身不能作为完整校准耗时。

## 6. 屏幕坐标映射

### 6.1 坐标链路

`landmark normalized → mirrored image coordinate → calibrated normalized coordinate → viewport CSS pixel → NDC → camera ray`

每个阶段必须有单元测试。

### 6.2 镜像规则

-   镜像开关只改变输入映射方向，不得同时在视频层和坐标层重复翻转。
-   UI 预览、指针位置和 3D 射线必须采用同一镜像定义。
-   左右手 handedness 翻转规则必须与实际视频镜像一致。

验收： - 镜像开/关分别完成四角指向测试。 -
指针方向与视频中手部运动方向一致。 -
左右手标签不因镜像开关发生错误双重翻转。

### 6.3 指针映射精度

测试目标： - 屏幕九点位置，每点 10 次。 -
每次记录目标点和指针稳定后的坐标。 - 计算平均误差、RMS、P95 和最大误差。

初始目标： - RMS ≤视口对角线 2%。 - P95 ≤视口对角线 3%。 - 最大误差
≤视口对角线 5%。

如果九点映射不能达标，不得通过增加 UI 磁性吸附来掩盖整体定位误差。

## 7. 三维场景射线映射

### 7.1 射线生成

-   使用映射后的 NDC 坐标。
-   由当前活动相机生成 Ray。
-   Ray origin 和 direction 使用当前相机变换。
-   对可交互对象执行 raycast。
-   排除虚拟手、指针装饰和不可交互辅助物。
-   根据对象可见、锁定、隐藏、工具模式确定是否参与命中。

### 7.2 多对象命中

-   默认采用最近有效命中对象。
-   若目标对象被锁定，不能静默穿透到后方对象；应显示锁定提示或按明确的选择策略处理。
-   同一屏幕位置存在多个对象时，显示当前命中对象名称。
-   进入连续操作后锁定 object ID，直到释放或取消。

### 7.3 命中精度

测试模型： - 平面。 - 球体。 - 立方体。 - 细长物体。 - 多对象重叠场景。

测试点： - 中心。 - 边缘。 - 轮廓附近。 - 前后重叠对象。

初始目标： - 对投影尺寸 ≥64×64 CSS px 的目标，命中选择成功率 ≥95%。 -
对目标轮廓附近的命中，单独报告误差，不得混入中心命中平均值。 -
多对象重叠时，100 次测试中错误对象命中 ≤1 次。

## 8. 工作平面与深度映射

### 8.1 V1 工作平面

当前 Inventory 的绘制实现使用相机前方固定距离 3.2 的平面。V1
必须把它明确称为"当前绘制平面"，不得描述为真实物理空间的自由三维绘制。

### 8.2 工作平面规格

-   工作平面与当前相机朝向保持定义关系。
-   用户开始绘制前能看到平面位置或平面边界。
-   平面位置在一次连续绘制过程中不可自动漂移。
-   相机改变时，正在进行的绘制不得意外改变坐标。
-   用户结束绘制后，轨迹保存为场景世界坐标对象。

### 8.3 深度控制拓展

若 V1 增加多层工作平面： - 默认层为 Z0。 -
用户通过明确的深度切换控件或约定手势选择 Z 层。 - 每层间距必须可配置。 -
当前层必须有明显视觉提示。 - 用户切换层时不得修改已完成轨迹。 -
深度切换误操作率目标 ≤1%。

具体层数、层间距和深度交互方式必须通过原型实验决定，不得凭空承诺真实深度感知。

## 9. 追踪丢失与恢复

状态： - TRACKING：追踪正常。 - LOW_CONFIDENCE：关键点质量不足。 -
OCCLUDED：短时遮挡。 - LOST_PENDING：短暂无结果。 - LOST：超时丢失。 -
RECOVERING：重新捕获。 - READY：恢复稳定，可接受新操作。

初始时间参数： - 无效输入 1 帧：立即冻结当前连续形变更新。 - 连续丢失
≤200ms：保留当前操作状态，但不使用旧坐标继续移动。 - 连续丢失
\>200ms：显示追踪中断提示。 - 连续丢失
≥450ms：结束或回滚当前操作，按具体操作规则处理。 - 重新捕获需连续 3
帧有效后恢复 READY。

验收： - 100 次追踪中断测试，0 次无限拖动。 - 0
次追踪恢复后对象无原因瞬移。 - 重新捕获 P95 ≤500ms。 -
追踪恢复不得自动重启已结束的按压或抓取。
